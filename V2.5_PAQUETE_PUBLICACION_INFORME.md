## 1. Qué se implementó

Un **paquete de publicación** autocontenido: al terminar una producción con MP4 final, se genera
junto al video un único `.md` (`<nombre>_<aspecto>_publicacion.md`) listo para revisar y publicar
en YouTube/Facebook, sin pedir título/descripción/CTA manualmente.

- Módulo nuevo **`publication_package.py`**: genera el `.md` desde el contexto de producción REAL.
- **No inventa datos**: cada campo sale del dict real que el caller pasa; si falta un dato escribe
  `No disponible`.
- **Tema conservado**: la idea original / Topic Lock siguen siendo la fuente de verdad del tema.
- **CTA**: se muestra **exactamente el CTA que ya eligió Production Intelligence** (el que vino en
  la producción). Este módulo NO crea un segundo sistema de CTA.
- Español neutro + tuteo, sin clickbait engañoso; hashtags controlados (sin abusar).
- Se genera **solo si existe MP4 final**. Si no hay MP4, NO crea un falso paquete (devuelve `None`
  y no escribe archivo).
- Respeto total de la arquitectura visual/narrativa existente: no se tocó Quality Gate, Topic Lock,
  Narrative Visual Director, selección de assets ni generación de imágenes.

## 3. Flujo final

```
IDEA
 → EDITORIAL
 → SCENES
 → ASSETS
 → QUALITY GATE
 → RENDER
 → MP4
 → PRODUCTION REPORT (informe_<tag>.json)
 → PUBLICATION PACKAGE (junto al MP4, solo si existe MP4 final)
```

- El Production Report técnico **no se elimina ni reemplaza**: sigue en `informe_<tag>.json`.
  El paquete de publicación responde "¿qué necesito para publicar?" y es complementario.

## 8. Problemas encontrados

1. **Formato/duración en tests**: expectativas mal calculadas a propósito (109.63s = 1:50, no 1:49;
   palabra "formato" con fallback existente). Ajustadas las aserciones, no el código.
2. **Relación de aspecto 16:9 mal detectada**: `_aspect_label("horizontal 16:9")` devolvía
   `vertical 9:16` porque la detección confundía la presencia de "9" y "16". Corregido con detección
   por orientación explícita (vertical/horizontal) ANTES que por dígitos; paquete del largo ya
   muestra `horizontal 16:9`. Cubierto con test de regresión (13).
3. **Warnings placeholder conviviendo con fallbacks reales**: el driver pasaba
   `["(ninguno registrado)"]` en `warnings` mientras también poblaba `fallbacks`, mostrando ambos.
   Corregido para no pasar el placeholder cuando hay fallbacks reales.

## 9. Limitaciones

- El paquete se genera a partir del dict de contexto que arma el caller (`producir_perdon_dual.py`).
  Está construido para integrarse a cualquier driver; el hook es `write_beside_mp4(context=..., 
  platform=...)`.
- Si el sistema captura plataforma vía `V2_PLATAFORMA`; si no se especifica y se necesita, el flujo
  interactivo vive en `production_intelligence.PlatformIntelligence.platform_prompt()` (pregunta
  "¿Para qué plataforma? YouTube, Facebook o ambas."). Esta fase no fuerza la pregunta si no hace
  falta para generar el video (default `both`).
- Los campos "Enfoque editorial" y "Fecha" los aporta el driver; en un futuro driver real deberían
  salir del plan/report. En esta prueba vienen de la producción real de perdón.
